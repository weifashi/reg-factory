# Google 统一运行入口与右侧日志

## 当前实现与未实现

Google 任务继续位于原 reg-factory 任务库，左侧参数和主运行按钮，右侧黑底日志与当前任务操作。不是另一个应用，也没有开放原项目未授权的执行 API。

本轮模拟模式是**任务编排测试**：预检、确认、持久创建、状态查询和暂停/取消/核验请求。不是 Google 注册/绑卡的模拟浏览器，也不生成假成功或假 worker 输出。真实模式禁用；真实 Google/银行/Sub2API 执行器仍未接入，模拟任务保持真实数据库状态（例如 QUEUED），不会凭定时动画变成成功。

```text
左侧参数 + 运行模拟任务
  -> 自动只读预检
       -> 不足/缺配置：右侧显示原因，不创建
       -> 合格：明确确认
            -> 取消确认：不创建
            -> 同意：创建足量批次
                 -> 自动选择首条任务
                 -> 当前状态 + 本页操作 + 服务端持久事件
                 -> 暂停 / 请求取消 / 排入只读核验
下方历史（折叠） -> 选旧任务 -> 读取状态与持久事件
高级检查（折叠） -> 保留旧手动预检/确认路径
```

## 日志来源

- `[本页操作]`：当前页面实际执行的检查/提交过程；刷新页面后不保留，不写浏览器 storage。
- `[服务端 #id]`：本人任务的数据库审计投影，刷新页面后可重新读取。仅创建、暂停、取消、核验四类操作，不读取秘密和任意外部日志。
- 最近 100 条按 ID 升序；更早内容存在时明确提示，非完整无限日志。无自动 POST 重试，刷新日志仅 GET。
- 接口或 DTO 失败显示“日志读取失败”，不伪造记录；已受理批次不因后续读取失败标成未知提交。

## 表字段、权限与原业务规则

0 新表、0 新字段、0 迁移。

新增 `GET /api/onboarding/tasks/{uuid}/events`：沿用 onboarding:read、当前会话与 owner 边界；业务只读查询 onboarding_tasks / onboarding_batches / audit_events。鉴权可能沿用原会话触碰与审计机制，不代表新日志接口有任务写副作用。

原批次创建仍使用既有 API；涉及的批次、任务、邮箱状态、租约、回执、审计写入规则没有替换。数量不足不缩水；仍在创建时重验资格和资源。暂停/取消不代表回滚外部操作或自动释放旧 hold；核验只记录请求。未知提交保留原请求键，不自动再建。

邮箱池、信用卡池、全局配置、原 16 项任务继续共享原壳；只复用已授权会话，不添加权限，不启用原任务执行接口。输入变化、页面失效或模式被篡改时不得继续新建。
