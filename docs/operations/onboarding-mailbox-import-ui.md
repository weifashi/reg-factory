# 邮箱导入页面交付记录 · 2026-09-29

## 页面 → 操作 → 结果
```
邮箱池 / 导入
  填分组（可空）和资料 → 检查资料 → 只读检查
    ├─ 有问题 → 显示行号、中文原因，不显示导入按钮
    └─ 无问题 → 显示“导入 N 条” → 沿用明确确认 → 导入结果
修改资料/分组 → 本次检查失效，重新检查
清空/离开/失效/完成/失败 → 按原规则清除输入
```

## 本轮文件与业务规则
- `webui/static/onboarding-pools.html`：导入页标题和描述改为面向用户的中文；收起的文本/JSON 示例仅展示、不预填；分组从默认 fixture:group 改为空（后台本来允许空，表示不分组）；输入框明确每行一条。去掉未接入的覆盖/换密占位按钮，未增加该功能。只保留“检查资料 / 清空”，检查通过才显示“导入 N 条”。简短保留当前仅测试凭据限制。
- `webui/static/onboarding-shell.css`：仅邮箱导入区的局部样式，960px 最大宽度、420px 分组宽度、190px 最小资料框高度、统一结果卡片及手机全宽导入按钮；复用原深色主题，未增加第二个页面外壳。
- `webui/static/onboarding-pools.js`：确认按钮随 preview 可见，内存中新增 count 用于按钮文字；接口计数字段必须是 0–1000 安全整数，否则拒绝展示可导入按钮。中文错误按固定字典映射，未知原因使用通用说明，不将外部内容作为 HTML。空分组展示“未分组”。仅展示待提交条数，不声称将新增相同数量。
- 去重规则不变：本次文本内重复/冲突属于检查问题，不能部分导入；与库中已有相同资料在提交时跳过，不覆盖。凭据不同仍走既有冲突流程。未知结果保留原请求键和摘要，需重新提供相同输入后核对，按钮显示“核对导入 N 条”。
- `tests/test_onboarding_unified_ui.py`：新增 8 项，覆盖空白初始状态、按钮分步、修改失效、问题不导入、无效计数、清空、导入成功、移动端和示例解析（金库策略验证包含在示例用例）。
- `tests/test_onboarding_pool_ui.py`：仅一处结果文案断言改为中文“账号状态仍待核验”。
