# 信用卡池管理（本轮交付范围）

## 大白话

原来只有一段“尚未接入”文字，现在在同一个 reg-factory 信用卡池入口中提供列表、手动添加、CSV 导入、编辑管理信息和启停。页面调用本项目 API，写入当前数据库，不用浏览器假数据模拟成功。

**当前存储仍只接受既有合成测试资料。没有放开真实银行卡资料，没有执行绑卡、扣款、申请赠金或自动分配。** 这次是卡池管理闭环，不是生产支付接入。管理权限为 `cards:manage`，没有该权限的账号看到说明和禁用操作；不会自动提权。

## 页面 -> 操作 -> 结果

```text
信用卡池
+-- 列表       -> 搜索 / 启用状态筛选 -> 本人卡片的脱敏分页结果
|              -> 编辑管理信息       -> 版本校验 + 保存 + 刷新列表
|              -> 停用卡片           -> 不再参与新分配；旧预留/关联不动
+-- 手动添加   -> 填完整测试资料      -> 同 CSV 管道生成脱敏预览
+-- CSV 导入   -> 粘贴 / 选文件       -> 检查格式、重复与冲突
               -> 明确确认           -> 原子写入 + 回执 + 审计
               -> 结果未知           -> 清空原文，保存原摘要/请求键
               -> 重新提供相同资料   -> 明确用原键核对，不自动重试
```

手工输入与批量输入共用服务，不新增另一套卡片判断规则。列表只显示别名、卡种、末四位、启停、账号上限、已关联数、预留数、待核对标记、版本和时间。余量是观察值，不能当成预留成功。

## 哪些资料可以修改

- 别名、账号上限、启停、短信渠道的非秘密引用。
- 上限不能低于“已关联 + 已预留”，数据库行锁后重新检查，不信任页面旧值。
- PAN 身份不可变；本轮没有卡号查看、CVV/OTP 输入或保存、账单地址回显、密钥下载、物理删除。
- 有效期、持卡人和地址在新增时录入，更新这些秘密资料需要后续独立的资料修订功能；不借重复导入覆盖旧记录。
- `>$50` 不作为强制条件；不查询或编造银行卡余额。

## 表字段和原规则

本轮**不新增表或字段，不运行迁移**。

| 表 | 写入 / 影响 |
|---|---|
| payment_cards | 新增复用原导入字段；编辑仅 alias/account_limit/sms_channel_ref/enabled、version、updated_at |
| secret_objects | 新增卡复用已有加密对象写入；列表和编辑管理信息不解密、不返回引用 |
| billing_identities | 新增卡建立账单身份；编辑管理信息不改变此表 |
| operation_receipts | 复用 card.import；新增 card.update 幂等回执，owner 范围原请求键 |
| audit_events | 复用导入/秘密审计；新增 card.update，仅版本等允许摘要 |
| card_reservations / card_account_links | 管理操作不新增、不释放、不手工改计数；原约束/投影保持 |

原“成功绑定才计已关联”“同卡只允许一个开放绑定”“未知结果保留占用”没有改成 UI 手动成功。已有最少关联优先候选规则不等于真实执行器接通。旧邮箱、任务、配置也继续共用同一会话和忙碌/未决请求保护。

## 安全和错误

- 后端从当前会话确定 owner；列表和每次写入重新检查权限。不能通过参数指定 owner、密钥路径、卡号指纹或计数。
- 浏览器只有一次会话读取；卡片模块没有另建认证。原文只在当前页面内存中，不写 storage、URL 或日志。离开卡片编辑/导入界面、会话失效或提交结束时清空导入原文。
- 分页游标绑定 owner/过滤条件/数据库目标并校验 MAC；变更条件后必须重新查询。
- CAS 版本冲突不自动覆盖；未知提交不自动生成新请求键。原五处“证明未提交”的接口没有扩展到卡接口。
- 会话失效后的迟到响应不能把卡片/预览填回来。

## 回退和验收

本轮未提交、推送或合并；预览来自现有 reg-factory 工作树。没有 schema 迁移，退回页面/路由/运行时变更即可停用新入口，但**不能删掉已导入卡、回执或审计**。数据库资料保留；真实生产资料尚不支持。
